# Stock Analysator

Веб-приложение для анализа акций US-рынка: вводишь тикер → получаешь метрики,
мультипликаторы, финансы и **DCF-оценку по трём сценариям** (Bear / Base / Bull).

Конечная цель владельца — сделать это частью портфолио (десктоп + мобилка).
Текущий приоритет — **чтобы работало локально на его Mac** и была точная DCF-модель.
Вопрос красивого деплоя/переписывания на «настоящий» веб-сайт отложен.

## Стек и запуск

- Модульная структура (Streamlit multipage + yfinance + plotly + pandas + numpy):
  - `app.py` — вход: конфиг страницы, сайдбар с DCF-слайдерами, приветствие.
  - `pages/` — вкладки: `Анализ`, `Сравнение`, `Избранное`.
  - `core/` — чистая логика: `data.py` (TickerData, safe, форматтеры, кэш-загрузка),
    `dcf.py` (`run_dcf`), `compare.py` (таблица сравнения), `favorites.py` (localStorage).
  - `ui/` — отрисовка: `theme.py` (CSS), `sidebar.py`, `components.py` (карточки/графики).
  - `tests/` — pytest для core-логики (`pytest` для прогона).
- Данные: Yahoo Finance через `yfinance` (без API-ключа), кэш `@st.cache_data`.
- Избранное хранится в браузере посетителя (`streamlit-local-storage`).
- Запуск (на Mac владельца `pip`/`streamlit` не в PATH — только через `python3 -m`):
  ```bash
  python3 -m pip install -r requirements.txt
  python3 -m streamlit run app.py
  ```
  Открывается на `http://localhost:8501`. Тесты: `python3 -m pytest`.

## Что уже есть в app.py

- Хедер компании (название, сектор, страна, сайт).
- Цена + дневное изменение, капитализация, EV, 52w High/Low, график цены за год.
- 8 мультипликаторов (P/E, Forward P/E, P/S, P/B, EV/EBITDA, EV/Revenue, PEG, Div. Yield).
- Финансы TTM (выручка, EBITDA, FCF, маржи, ROE/ROA, рост выручки).
- **DCF — три сценария** со слайдерами в сайдбаре (горизонт, WACC, терм. рост,
  стартовый рост FCF для Bull/Base/Bear).
- Графики: структура стоимости (Base), справедливая цена vs текущая, история финансов.

## DCF-модель (важно — недавно переделана)

Функция `run_dcf()`. Ключевое изменение: перешли с постоянного роста на
**2-фазную модель с затуханием**. Стартовый рост (1-й год) линейно спадает к
терминальному росту к концу горизонта — чтобы убрать нереалистичное
компаундирование (напр. 20%/год все 5 лет) и завышенные оценки.

- В карточках сценариев показывается: `стартовый% → конечный%`, апсайд и
  **доля терминальной стоимости** (TV / enterprise value).
- Если TV-доля > 75% — выводится предупреждение (оценка держится на допущениях
  о WACC/терм. росте, а не на прогнозе FCF).
- Дефолтные стартовые ставки: Bull 15%, Base 8%, Bear 2%.

### База FCF (`core/data.py`)

- Не единичный TTM-FCF из Yahoo, а **медиана годовых FCF** (сглаживает лумпи-капекс:
  у AMZN год стройки ЦОД занижал TTM до $9.8B при медиане $32B).
- По умолчанию **за вычетом SBC** (галочка в сайдбаре). SBC вычитается по каждому
  году отдельно, потом берётся медиана — корректнее, чем медиана минус медиана.
- FCF ≤ 0 (напр. INTC) → DCF не считается, показывается понятное объяснение.

### Реверс-DCF и чувствительность (`core/dcf_analysis.py`)

- `implied_growth()` — какой стартовый рост FCF заложен в текущую цену.
- `implied_return()` — какую годовую доходность даёт покупка по текущей цене
  при росте Base-сценария.
- Обе решаются бисекцией (справедливая цена монотонна по росту и по ставке);
  нет решения в диапазоне → `None` и честное «не определяется» на экране.
- `sensitivity_grid()` — сетка 5×5 «WACC ±2 п.п. × терм. рост ±1 п.п.»,
  в ячейках апсайд и цена; где терм. рост ≥ WACC — пусто.

### ⚠️ Известная проблема калибровки (не решена)

При дефолтах (WACC 10%, горизонт 5 лет) модель даёт ~17x FCF, тогда как
качественные мега-капы торгуются по 30–40x FCF. Из-за этого DCF систематически
показывает их «дорогими», а реверс-DCF выдаёт неправдоподобный заложенный рост
(AAPL 77%, KO 97%). Математика верна (round-trip тесты), проблема в дефолтах.
Кандидаты на исправление: WACC из беты по CAPM (для мега-капов ~8%, а не 10%),
горизонт по умолчанию 10 лет вместо 5.
