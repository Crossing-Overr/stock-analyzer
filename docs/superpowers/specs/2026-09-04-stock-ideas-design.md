# «Подборка идей» — дизайн

**Дата:** 2026-09-04
**Статус:** утверждён владельцем, готов к плану реализации

## Цель

Новая вкладка «💎 Идеи»: приложение само предлагает **акции, к которым стоит
присмотреться** — где хороший FCF, где DCF показывает апсайд по текущей цене,
где большой потенциал за небольшие деньги. Не голый скринер, а **курируемая
подборка** через пресеты (плюс тонкая настройка фильтрами).

## Решения владельца

- **Набор тикеров:** S&P 500 (готовый список).
- **Управление:** готовые пресеты + пара ползунков тонкой настройки.
- **Расчёт:** снимок в репо, обновляется командой (не живой скан — 500 акций
  живьём это ~15 мин и риск бана Yahoo).
- **5 пресетов**, включая turnaround (высокий риск / высокий ревард).

## Архитектура

```
scripts/build_snapshot.py   →   data/sp500_snapshot.json   →   приложение читает
(вручную, ~15 мин)              (коммитится, дата внутри)         (мгновенно, кэш)
                                                                        ↓
                                                          core/screener.py
                                                          (пресет + фильтры + сортировка)
                                                                        ↓
                                                          pages/4_💎_Идеи.py — карточки
```

Приложение к Yahoo для подборки НЕ обращается — всё из снимка. Клик по карточке
открывает вкладку Анализ (там уже живые данные).

### `data/sp500.txt`

Статический список ~500 тикеров S&P 500, по одному в строке. Состав индекса
меняется медленно — обновляем файл вручную раз в несколько месяцев.

### `scripts/build_snapshot.py`

Прогоняет каждый тикер из `sp500.txt` через существующие модули
(`load_ticker`, `wacc.estimate_wacc`, `data.load_risk_free`, `dcf.run_dcf`,
`dcf_analysis.implied_growth/implied_return`) и пишет `data/sp500_snapshot.json`.

- Устойчивость: прогресс в stdout, пауза между запросами (throttle),
  продолжение с места обрыва (доливает в существующий JSON, пропускает уже
  посчитанные), аккуратная обработка битых тикеров (пропуск с пометкой).
- Для каждого тикера в снимок кладём готовые поля (чтобы фильтры считались
  мгновенно, без пересчёта DCF):
  `symbol, name, sector, price, market_cap, pe, fcf_base, fcf_positive,
  fcf_multiple (market_cap/fcf_base), wacc, upside_base (%), implied_growth,
  implied_return, revenue_growth, roe, net_margin,
  price_pct_of_52w_range (0..1), dcf_applicable (bool)`.
- Банки и убыточные (где FCF-DCF неприменим) → `dcf_applicable=false`; в
  подборку с DCF-критериями не попадают.
- Верхний уровень JSON: `{"as_of": "<ISO-дата>", "rf": <ставка 10-леток>,
  "count": N, "tickers": [...]}`. `rf` нужен пресету «Высокая доходность»
  (сравнение implied_return с безрисковой ставкой).
- Параметры расчёта фиксированы = дефолтам приложения (auto-WACC по CAPM,
  горизонт 10 лет, SBC вычитается) — чтобы подборка была согласована с тем, что
  покажет вкладка Анализ по умолчанию.

### `core/screener.py` (чистая логика, TDD)

Читает снимок, применяет пресет и пользовательские фильтры, ранжирует, отдаёт
топ-N. Не знает про Streamlit и yfinance.

```python
PRESETS: dict[str, Preset]          # id → Preset(label, describe, predicate, sort_key, badge)
load_snapshot(path) -> Snapshot     # {as_of, tickers: list[dict]}
screen(snapshot, preset_id, filters, limit=20) -> ScreenResult
```

`filters` — dataclass с ползунками (min_upside, max_pe, min_revenue_growth;
require_positive_fcf всегда True). `ScreenResult` — `as_of`, `total_passed`,
`rows` (отсортированные, обрезанные до limit).

### 5 пресетов

| id | Ярлык | Фильтр | Сортировка |
|---|---|---|---|
| `undervalued` | 💎 Недооценённые с FCF | `dcf_applicable · upside>0 · fcf_positive · pe<30` | по upside ↓ |
| `growth_cheap` | 🚀 Рост за небольшие деньги | `implied_growth < revenue_growth · fcf_multiple < 20` | по (revenue_growth − implied_growth) ↓ |
| `quality_discount` | 🏆 Качество со скидкой | `roe>0.15 · net_margin>0.10 · upside>−10%` | по (нормир. качество + upside) ↓ |
| `high_return` | 💰 Высокая доходность | `implied_return > snapshot.rf · fcf_positive` | по implied_return ↓ |
| `turnaround` | 🔄 Turnaround | `price_pct_of_52w_range < 0.33 · fcf_positive · (roe или margin выше медианы) · upside>0.30 · revenue_growth низкий` | по upside ↓ |

Пользовательские ползунки применяются **поверх** пресета (пересекаются с его
фильтром). `require_positive_fcf` неизменно True — без положительного FCF DCF
бессмысленен.

Turnaround-строки помечаются `badge="risk"`.

### `pages/4_💎_Идеи.py`

- 5 кнопок-пресетов (активный подсвечен), выбор в `session_state`.
- Компактная строка тонкой настройки: ползунки min_upside, max_pe,
  min_revenue_growth; отметка «только положительный FCF» (только индикатор).
- Строка статуса: «Данные на {as_of} · {total_passed} компаний прошло фильтр ·
  топ-{limit}».
- Карточки-строки (как в мокапе): слева тикер/имя/цена, по центру крупно
  справедливая цена + апсайд (цветом), справа заложенный vs фактический рост и
  P/E. У turnaround — фиолетовый оттенок и бейдж «⚠️ РИСК».
- Клик по карточке → переход на вкладку Анализ с этим тикером (через
  `st.session_state` + `st.switch_page`).
- Жёсткий дисклеймер: подборка — не сигнал к покупке, а список «куда посмотреть
  внимательнее»; DCF-апсайд чувствителен к допущениям; turnaround —
  максимальный риск.
- Если `snapshot.json` отсутствует → аккуратное сообщение «Снимок ещё не
  построен, запусти `python3 scripts/build_snapshot.py`».

## Данные и свежесть

На экране всегда видна дата снимка. Обновление = `python3
scripts/build_snapshot.py` + `git push` (как деплой). Подборка — отправная
точка; клик открывает Анализ с живой ценой и полным DCF.

## Тестирование

- `tests/test_screener.py` (TDD): каждый пресет фильтрует и сортирует корректно
  на маленьком синтетическом снимке; ползунки сужают выборку; пустой результат
  обрабатывается; turnaround проставляет badge; `dcf_applicable=false`
  исключается из DCF-пресетов.
- `build_snapshot.py` не покрывается юнит-тестами (сетевой), но переиспользует
  уже протестированные core-модули; проверяется запуском на маленьком списке.
- Существующие 72 теста не ломаются (новый код изолирован).

## Краевые случаи

- Нет снимка → понятное сообщение, не падение.
- Пустой результат фильтра → «ничего не найдено, ослабь фильтры».
- Старый снимок → дата на экране; можно добавить пометку «>30 дней» позже (не в
  этой итерации, YAGNI).
- Состав S&P 500 устарел → список статический, обновляется отдельно.

## Ограничения (осознанные, вне scope)

- Не живой скан всего рынка (yfinance не позволяет быстро и надёжно).
- Не автообновление снимка (на free Streamlit Cloud нет планировщика) — вручную.
- Turnaround-прокси не отличает временный спад от структурного упадка — это
  подчёркнуто в UI как максимальный риск.

## Дисклеймер

Усиленный на этой вкладке: только для образовательных целей, не инвестиционная
рекомендация, подборка не является сигналом к покупке.
