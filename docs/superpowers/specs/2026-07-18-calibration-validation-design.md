## Цель

Устранить известную проблему калибровки (см. CLAUDE.md): при дефолтах
WACC 10% / горизонт 5 лет модель даёт ~17x FCF против рыночных 30–40x для

реверс-DCF выдаёт абсурдный заложенный рост (AAPL 77%, KO 97%).

Плюс: систематическая валидация всех отображаемых цифр, логики модели,
актуальности данных и адекватности результатов.

## Часть 1 — Калибровка

### A. WACC из CAPM (`core/wacc.py` — новый модуль)

Функция `estimate_wacc(beta, risk_free, market_cap, total_debt) -> WaccEstimate`:

- **Cost of equity (CAPM):** `Re = rf + β × ERP`, `ERP = 0.05` (константа, стандартная
  премия рынка США).
- **Risk-free:** живая доходность 10-летних гособлигаций из yfinance (`^TNX`,
  `regularMarketPrice / 100`); недоступна → константа `0.045`. Кэшируется
  `@st.cache_data(ttl=3600)` в `core/data.py` (`load_risk_free()`), чтобы не
  дёргать Yahoo на каждый rerun.
- **Учёт долга (упрощённый полный WACC):**
  `WACC = (E×Re + D×Rd×(1−0.21)) / (E+D)`, где `Rd = rf + 0.01`,
  `E = market_cap`, `D = total_debt` (0 если нет данных).
- **Ограничители:** бета клампится в `[0.5, 2.5]` (β=0.35 у KO — статистический
  артефакт); итоговый WACC клампится в `[0.065, 0.16]`.
- **Фолбэки:** нет беты или нет market_cap → вернуть `None` (UI откатится на
  ползунок и покажет причину).
- `WaccEstimate` — dataclass: `wacc`, `cost_of_equity`, `risk_free`, `beta_used`
  (после клампа), `beta_raw`, `debt_weight` — чтобы UI мог показать разбор.

Чистая функция, TDD. Пороговые значения — именованные константы модуля.

### B. Сайдбар (`ui/sidebar.py`)

- Галочка **«WACC автоматически (CAPM по бете)»**, `key="dcf_wacc_auto"`,
  по умолчанию **включена**.
- Включена → ползунок WACC скрывается (не рендерится), итоговый WACC приходит
  из CAPM. Выключена → ползунок как сейчас.
- Проблема: CAPM-WACC зависит от тикера, а сайдбар рендерится до загрузки
  тикера. Решение: сайдбар возвращает `DcfParams` с `wacc_mode: str`
  ("auto"/"manual") и `wacc_manual: float` (значение ползунка). Страница после
  загрузки `TickerData` вычисляет действующий WACC:
  `effective_wacc = estimate_wacc(...).wacc если auto и есть данные, иначе wacc_manual`.
  Все расчёты страницы (DCF, реверс, сетка) используют `effective_wacc`.
- Под галочкой на странице Анализ показывается разбор:
  `WACC 9.9% = rf 4.5% + β 1.10 × ERP 5.0% (долг учтён)` — рендерится на
  странице (не в сайдбаре), т.к. требует данных тикера. При фолбэке — причина:
  «нет беты — используется ползунок».
- Страницы Сравнение и Избранное используют тот же `effective_wacc` per-ticker
  (у каждого тикера своя бета → свой WACC при auto).

## Часть 2 — Валидация (`validate.py` в корне)

Скрипт запускается вручную: `python3 validate.py [ТИКЕР ...]`. Дефолтная
корзина: AAPL, MSFT, NVDA, AMZN, KO, T, JPM, INTC, TSLA + заведомо битый
тикер ZZZZXX (ожидание: аккуратный отказ, не трейсбек).

Каждая проверка печатает `✅ / ⚠️ / ❌` с фактическими цифрами. Выход с кодом 1,
если есть ❌. Группы проверок:

1. **Согласованность данных** (для каждого тикера):
   - P/E ≈ цена / EPS (`trailingEps`), допуск ±10%;
   - кап-я ≈ цена × акции, допуск ±5%;
   - EV ≈ кап-я + чистый долг, допуск ±15% (лизинг/миноритарии дают шум);
   - маржи в [−100%, 100%]; ROE в [−300%, 300%];
   - див. доходность в [0, 15%];
   - 52wLow ≤ цена ≤ 52wHigh с допуском ±2%.

2. **Логика модели:**
   - FCF из отчёта ≈ OCF − |capex|, допуск ±5% (сверка строк cashflow);
   - round-trip реверс-DCF на живых данных: `implied_growth(цена(g=8%)) ≈ 8%`;
   - монотонность сценариев: Bull ≥ Base ≥ Bear;
   - TV-доля Base < 80% при горизонте 10 лет;
   - SBC: `fcf_ex_sbc < fcf` там, где SBC есть.

3. **Адекватность результатов** (при дефолтных настройках, auto-WACC):
   - заложенный рост для прибыльных мега-капов в [−10%, 40%];
   - fair-value мультипликатор Base (equity value / FCF base) в [10x, 45x];
   - ожидаемая доходность в [2%, 12%];
   - INTC (FCF < 0): DCF корректно отказывается, реверс возвращает None.

4. **Актуальность данных:**
   - цена не старше 3 торговых дней (по `history.index[-1]`);
   - последний годовой отчёт не старше 18 месяцев;
   - rf из ^TNX в разумном диапазоне [1%, 10%].

**Найденные проблемы чинятся в рамках этой же работы** — скрипт инструмент,
фиксы результат. Скрипт остаётся в репо для перепроверки после любых изменений.
