# «Умный DCF» — дизайн

**Дата:** 2026-07-16
**Статус:** утверждён владельцем, готов к плану реализации

## Цель

Повысить точность и осмысленность DCF-оценки. Сейчас приложение отвечает
«сколько стоит акция при моих допущениях». После этой работы оно отвечает на
более честный вопрос инвестора: **«какой рост уже заложен в текущую цену,
сколько я на этом заработаю и насколько оценка устойчива к допущениям»**.

Три фичи одним пакетом:

1. **Реверс-DCF** — заложенный рост FCF и ожидаемая доходность.
2. **Таблица чувствительности** — сетка WACC × терминальный рост.
3. **Поправка на SBC** — вычитание компенсации акциями из FCF.

Плюс фикс: ползунки сайдбара сбрасываются при переходе между вкладками.

## Решения владельца

- Реверс-DCF показывает **обе** величины: заложенный рост И ожидаемую доходность.
- SBC-поправка — **галочка в сайдбаре, включена по умолчанию**.
- Ячейки чувствительности — **апсайд % с подсветкой**, плюс переключатель на
  режим «справедливая цена $».
- **Критично:** все новые блоки должны пересчитываться при движении ползунков.

## UX (вкладка «Анализ»)

### A. Блок «🔍 Что заложено в цену» (под карточками сценариев)

Две карточки:

- **Заложенный рост FCF** — например «24%/год → 2.5%». Рядом для сравнения
  фактический рост выручки за последний год (`revenue_growth`, уже есть в
  `TickerData`). Позволяет увидеть, оптимистичнее ли рынок, чем реальность.
- **Ожидаемая доходность** — например «6.2%/год»: если рост будет как в
  Base-сценарии, столько даст покупка по текущей цене. В подписи — ориентир:
  доходность 10-летних гособлигаций США ≈ 4% (константа в тексте, не тянем из сети).

### B. Таблица чувствительности (под графиками DCF, в `st.expander`)

- Сетка 5×5: **WACC** = текущий ±2 п.п. шагом 1 п.п.; **терминальный рост** =
  текущий ±1 п.п. шагом 0.5 п.п.
- Переключатель над сеткой: **Апсайд %** (по умолчанию, с зелёно-красной
  подсветкой) / **Справедливая цена $**.
- Ячейка с текущими настройками ползунков выделена рамкой.
- Ячейки, где терминальный рост ≥ WACC, показывают «—» (модель Гордона
  неприменима).

### C. Галочка «Вычитать SBC из FCF» (сайдбар, включена по умолчанию)

В подписи под карточками DCF видно базу: `База FCF: $28.4B (за вычетом SBC $3.8B)`.

Сравнение и Избранное новых блоков не получают, но их апсайд Base автоматически
становится точнее за счёт SBC-поправки.

## Архитектура

### Новый модуль `core/dcf_analysis.py`

`core/dcf.py` остаётся чистой моделью (`run_dcf`, `dcf_upside_base`). Анализы
поверх модели живут отдельно:

```python
implied_growth(price, fcf_base, shares, net_debt, wacc, terminal_growth, years) -> Optional[float]
implied_return(price, fcf_base, shares, net_debt, growth_start, terminal_growth, years) -> Optional[float]
sensitivity_grid(fcf_base, price, shares, net_debt, growth_start, wacc, terminal_growth, years) -> SensitivityGrid
```

`SensitivityGrid` — dataclass: список WACC, список терминальных ростов, матрица
ячеек. Каждая ячейка содержит и апсайд, и справедливую цену (`None`, если
терм. рост ≥ WACC), чтобы переключатель режима не требовал пересчёта.

Сетка чувствительности считается по **стартовому росту Base-сценария** (значение
ползунка «📊 Base»): варьируются только WACC и терминальный рост, рост остаётся
базовым. Реверс-DCF `implied_return` тоже опирается на рост Base-сценария.

### Метод решения — бисекция

Справедливая цена монотонна по обоим искомым параметрам: растёт с ростом FCF и
падает с ростом ставки дисконтирования. Поэтому решение надёжно зажимается
делением отрезка пополам (~50 итераций, мгновенно), без риска расхождения.

- **Заложенный рост** ищем в диапазоне −50% … +100%.
- **Ожидаемая доходность** — в диапазоне (терминальный рост + 0.1 п.п.) … 50%.
  Ниже терминального роста модель Гордона ломается (знаменатель ≤ 0).
- Если решения в диапазоне нет — возвращаем `None`. На экране честное «не
  определяется в диапазоне», а не выдуманное число.

### `core/data.py`

Из отчёта о ДДС достаём строку `Stock Based Compensation`. FCF за вычетом SBC
считаем **по каждому году отдельно**, затем берём медиану — это корректнее, чем
вычитать медиану SBC из медианы FCF. Переиспользуем существующий `normalize_fcf`.

Новые поля `TickerData`:
- `fcf_normalized_ex_sbc: Optional[float]`
- `sbc_normalized: Optional[float]`

Нет данных по SBC → оба поля `None`, галочка ни на что не влияет, в подписи
пометка. Знак SBC в yfinance проверить на живых данных при реализации: ожидается
положительная добавка в операционный поток, т.е. `FCF_ex_SBC = FCF − SBC`.

### `ui/sidebar.py`

- Галочка `Вычитать SBC из FCF` (по умолчанию `True`).
- **Всем ползункам добавить `key=`**, чтобы значения жили в `st.session_state` и
  не сбрасывались при переходе между вкладками (сейчас сбрасываются).
- `DcfParams` получает поле `subtract_sbc: bool`.

### `ui/components.py`

- Карточки реверс-DCF (переиспользуют существующий стиль `.metric-card`).
- Рендер сетки чувствительности — HTML-таблица с подсветкой, по образцу таблицы
  на вкладке Сравнение (классы `.cmp-best` / `.cmp-worst` или аналогичные).

### Реактивность

Все новые блоки читают значения из `DcfParams`, который возвращает
`render_sidebar()` на каждом перезапуске скрипта. Streamlit перезапускает
страницу при любом движении ползунка, поэтому заложенный рост, ожидаемая
доходность и вся сетка чувствительности пересчитываются автоматически.

## Краевые случаи

- **FCF ≤ 0** (INTC): новые блоки показывают то же понятное сообщение «DCF
  неприменим», что и существующие карточки сценариев.
- **Терм. рост ≥ WACC** в сетке: ячейка «—».
- **Нет данных SBC**: галочка неактивна по смыслу, база = обычный нормализованный FCF.
- **Нет решения у бисекции**: честное «не определяется в диапазоне».
